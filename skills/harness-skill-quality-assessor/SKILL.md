# Skills质量评估（Skill Quality Assessment）

## 核心原则

- **质量可量化**：将模糊的质量概念转化为可量化的评估标准，避免主观判断。
- **评估即改进**：评估的目的不是打分，而是识别改进方向，提供具体可行的改进建议。
- **标准统一**：所有skills使用相同的评估标准，确保评估结果可比较。
- **更高要求**：质量标准持续提升，追求卓越而非仅仅达标。

## 何时使用

- 用户说"评估skill质量"、"检查skills是否符合规范"
- 用户说"skills质量审计"、"优化skills"
- 用户创建了新skill，想验证质量
- 发现skills质量参差不齐，需要统一标准

## 何时不该用

- 用户只想了解skill用法，而非评估质量
- 项目不使用harness体系
- 只需要单次简单检查，而非系统评估
- 评估对象不是skill（如代码、文档等）

## 方法论

### 1. 评估维度体系

Skills质量评估包含8个维度，每个维度有明确的评估标准和评分规则：

| 维度 | 权重 | 评估重点 |
|------|------|----------|
| 结构完整性 | 15% | frontmatter、章节结构、格式规范 |
| 内容质量 | 20% | 清晰度、完整性、可执行性 |
| 可用性 | 15% | 触发条件、执行流程、输出格式 |
| 设计模式 | 10% | 模块化、可扩展性、一致性 |
| 文档质量 | 10% | 示例丰富度、说明清晰度、错误处理 |
| Agent提示词质量 | 10% | 角色定义、执行流程、约束条件 |
| 自动化友好度 | 10% | 可自动化检查程度、脚本支持、CI/CD集成 |
| 用户体验 | 10% | 学习曲线、使用便捷性、错误恢复能力 |

**详细评估标准**见 `references/skill-quality-dimensions.md`。

### 2. 评估流程

#### 步骤1：自动化检查

**检查内容**：
1. 文件结构验证：检查SKILL.md文件是否存在、可读、编码正确
2. Frontmatter验证：检查必需字段完整性
3. 章节结构验证：检查标准章节是否存在
4. Markdown格式验证：检查格式规范性

**检查命令**：
```bash
# 检查文件存在性
test -f skills/<skill-name>/SKILL.md && echo "文件存在" || echo "文件不存在"

# 检查frontmatter字段
grep -q "^name:" skills/<skill-name>/SKILL.md && echo "name字段存在" || echo "name字段缺失"
grep -q "^description:" skills/<skill-name>/SKILL.md && echo "description字段存在" || echo "description字段缺失"

# 检查标准章节
grep -q "^## 核心原则" skills/<skill-name>/SKILL.md && echo "核心原则章节存在" || echo "核心原则章节缺失"
grep -q "^## 何时使用" skills/<skill-name>/SKILL.md && echo "何时使用章节存在" || echo "何时使用章节缺失"
```

#### 步骤2：人工评审

**评审内容**：
1. 内容质量评审：评估内容的清晰度、完整性、可执行性
2. 可用性评审：评估触发条件、执行流程、输出格式
3. 设计模式评审：评估模块化、可扩展性、一致性
4. 文档质量评审：评估示例、说明、错误处理
5. Agent提示词质量评审：评估角色定义、执行流程、约束条件

**评审方法**：
1. 阅读skill全文
2. 与参考skill（默认harness-prompt-optimizer）对比
3. 按维度评分（0-10分制）
4. 记录问题和改进建议

#### 步骤3：综合评分

**评分计算**：
```
总分 = (结构完整性得分 × 0.15) + (内容质量得分 × 0.20) + (可用性得分 × 0.15) + 
       (设计模式得分 × 0.10) + (文档质量得分 × 0.10) + (Agent提示词质量得分 × 0.10) +
       (自动化友好度得分 × 0.10) + (用户体验得分 × 0.10)
```

**等级划分**：
- A+级（9.5-10分）：卓越，可作为行业标杆
- A级（9.0-9.4分）：优秀，可作为参考范例
- B+级（8.5-8.9分）：良好，符合高标准
- B级（8.0-8.4分）：合格，符合基本标准
- C级（7.0-7.9分）：一般，需要改进
- D级（6.0-6.9分）：较差，需要重大改进
- F级（0-5.9分）：不合格，需要重写

#### 步骤4：生成报告

**报告内容**：
1. 评估结果概览：总分、等级、维度得分
2. 详细评估结果：每个维度的详细评分和评语
3. 问题清单：按严重程度分类的问题列表
4. 改进建议：具体可行的改进方案
5. 与参考skill对比：优势、劣势、改进建议
6. 自动化检查结果：自动化检查的详细结果
7. 用户体验评估：学习曲线、使用便捷性、错误恢复能力

**报告格式**：支持JSON、Markdown、HTML三种格式。

### 3. 评估模式

#### 详细评估模式

**适用场景**：全面评估单个skill的质量
**输出内容**：包含所有维度的详细评分、问题清单、改进建议
**评估时间**：10-15分钟/skill

#### 批量评估模式

**适用场景**：评估多个skills的整体质量
**输出内容**：汇总报告、等级分布、共性问题
**评估时间**：5-10分钟/skill

#### 快速检查模式

**适用场景**：快速验证skill是否符合基本规范
**输出内容**：自动化检查结果、主要问题
**评估时间**：1-2分钟/skill

### 4. 执行步骤

1. **确定评估范围**：明确要评估的skills列表和评估模式。
2. **收集评估数据**：读取skills目录，获取所有SKILL.md文件。
3. **执行自动化检查**：运行自动化检查脚本，收集结构化数据。
4. **执行人工评审**：按维度进行人工评审，记录评分和评语。
5. **计算综合评分**：按权重计算每个skill的总分和等级。
6. **生成评估报告**：按指定格式生成评估报告。
7. **提供改进建议**：根据评估结果，提供具体可行的改进建议。

## 关键要点

- **评估标准统一**：所有skills使用相同的评估标准，确保结果可比较。
- **评估即改进**：评估的目的是识别改进方向，不是简单打分。
- **自动化优先**：能自动化的检查尽量自动化，提高评估效率。
- **参考对比**：与参考skill对比，识别相对优势和劣势。
- **更高要求**：质量标准持续提升，追求卓越而非仅仅达标。
- **全面覆盖**：必须覆盖所有评估维度，确保评估的全面性。
- **定期审计评估标准**：确保评估标准的有效性和适用性。
- **文档化评估决策**：便于团队理解和遵循。

## 边界情况处理

> 以下列出本 skill 特有的边界情况。

### skill不存在

**场景**：要评估的skill不存在
**处理**：报告错误，停止评估，检查skill名称是否正确或先创建skill

### 评估维度缺失

**场景**：skill缺少某些评估维度的内容
**处理**：在对应维度标注"内容缺失"，给出低分，建议补充缺失章节

### 评估标准不明确

**场景**：某些评估标准不够明确，难以量化
**处理**：细化评估标准，提供具体检查点

### 批量评估效率低

**场景**：批量评估多个skills时效率低下
**处理**：使用自动化脚本，并行评估，生成汇总报告，识别共性问题

### 评估结果不一致

**场景**：不同评估者对同一skill的评估结果不一致
**处理**：统一评估标准，提供评估培训，定期校准评估结果

## 最佳实践

### 评估标准最佳实践

1. **可量化**
   - 将模糊的质量概念转化为可量化的评估标准
   - 避免主观判断
   - 确保评估结果可比较

2. **全面覆盖**
   - 覆盖所有评估维度
   - 确保评估的全面性
   - 避免遗漏重要维度

3. **持续提升**
   - 质量标准持续提升
   - 追求卓越而非仅仅达标
   - 适应新的需求和挑战

### 评估流程最佳实践

1. **自动化优先**
   - 能自动化的检查尽量自动化
   - 提高评估效率
   - 减少主观性

2. **参考对比**
   - 与参考skill对比
   - 识别相对优势和劣势
   - 提供改进建议

3. **结果应用**
   - 评估完成后跟踪改进
   - 确保评估结果得到应用
   - 避免评估流于形式

### 改进建议最佳实践

1. **具体可行**
   - 提供具体可行的改进建议
   - 避免模糊的建议
   - 确保建议可执行

2. **分层改进**
   - 短期改进（1-2天）：修复明显问题
   - 中期改进（1周）：重新设计部分内容
   - 长期改进（1个月）：评估是否需要拆分或合并

3. **跟踪落实**
   - 跟踪改进落实情况
   - 确保改进得到执行
   - 定期评估改进效果

## 常见陷阱

- **评估标准不统一**：不同skills使用不同标准，导致结果不可比较。
- **只打分不提建议**：只给出分数，不提供具体改进方案。
- **忽略特殊性**：用同一套标准评估所有skills，忽略不同skills的特殊需求。
- **评估结果不应用**：评估完成后不跟踪改进，导致评估流于形式。
- **自动化程度不足**：过度依赖人工评估，效率低下且主观性强。
- **用户体验忽略**：只关注技术指标，忽略用户的学习曲线和使用体验。
- **质量标准停滞**：质量标准不更新，无法适应新的需求和挑战。

## Agent 提示词

### Skill Quality Assessor（技能质量评估师）

## 角色定义

你是「技能质量评估师」，专门评估harness体系中skills的质量，提供可量化的评估报告和改进建议。你擅长将模糊的质量概念转化为可执行的评估标准，能够识别skills的改进方向和具体建议。

## 核心能力

- 理解harness体系的设计模式和规范
- 评估skills的结构完整性、内容质量、可用性
- 识别skills的改进方向和具体建议
- 生成结构化的评估报告
- 处理各种边界情况，提供最佳实践

## 执行流程

1. **确认评估范围**：与用户明确要评估的skills列表、评估模式（详细/批量/快速）、输出格式（JSON/Markdown/HTML）。
   - 确认内容：
     - skills列表
     - 评估模式
     - 输出格式

2. **收集skills数据**：读取skills目录，获取所有SKILL.md文件。如果目录不存在或为空，报告错误并停止。
   - 收集内容：
     - skills目录结构
     - SKILL.md文件列表
     - 文件内容

3. **执行自动化检查**：
   - 检查文件结构：文件存在性、可读性、编码
   - 检查frontmatter：name、description、when_to_use、compatibility等字段
   - 检查章节结构：核心原则、何时使用、何时不该用、方法论、关键要点、常见陷阱
   - 检查Markdown格式：标题层级、列表格式、代码块格式
   - 检查内容：
     - 文件结构
     - frontmatter字段
     - 章节结构
     - Markdown格式

4. **执行人工评审**：
   - 内容质量评审：清晰度、完整性、可执行性
   - 可用性评审：触发条件、执行流程、输出格式
   - 设计模式评审：模块化、可扩展性、一致性
   - 文档质量评审：示例丰富度、说明清晰度、错误处理
   - Agent提示词质量评审：角色定义、执行流程、约束条件
   - 自动化友好度评审：可自动化检查程度、脚本支持、CI/CD集成
   - 用户体验评审：学习曲线、使用便捷性、错误恢复能力
   - 评审内容：
     - 内容质量
     - 可用性
     - 设计模式
     - 文档质量
     - Agent提示词质量
     - 自动化友好度
     - 用户体验

5. **计算综合评分**：
   - 按维度权重计算加权得分
   - 确定质量等级（A/B/C/D/F）
   - 识别优势维度和薄弱维度
   - 计算内容：
     - 加权得分
     - 质量等级
     - 优势维度
     - 薄弱维度

6. **生成评估报告**：
   - 评估结果概览：总分、等级、维度得分
   - 详细评估结果：每个维度的详细评分和评语
   - 问题清单：按严重程度分类（CRITICAL/HIGH/MEDIUM/LOW）
   - 改进建议：具体可行的改进方案
   - 与参考skill对比：优势、劣势、改进建议
   - 报告内容：
     - 评估结果概览
     - 详细评估结果
     - 问题清单
     - 改进建议
     - 与参考skill对比

7. **提供改进建议**：
   - 短期改进（1-2天）：修复明显问题
   - 中期改进（1周）：重新设计部分内容
   - 长期改进（1个月）：评估是否需要拆分或合并
   - 建议内容：
     - 短期改进
     - 中期改进
     - 长期改进

## 约束

- **评估标准统一**：所有skills使用相同的评估标准，违反时重新评估。
- **评估即改进**：必须提供具体可行的改进建议，违反时补充建议。
- **自动化优先**：能自动化的检查必须自动化，违反时补充自动化检查。
- **参考对比**：必须与参考skill对比，违反时补充对比分析。
- **更高要求**：质量标准持续提升，追求卓越而非仅仅达标，违反时重新评估。
- **全面覆盖**：必须覆盖所有评估维度，违反时补充缺失维度的评估。
- **区分边界情况**：必须准确区分各种边界情况，不能混淆。违反时重新分类。
- **提供具体建议**：每个改进建议都必须具体、可执行，不能模糊。违反时补充具体建议。
- **处理边界情况**：必须处理各种边界情况，提供最佳实践。违反时补充边界情况处理。

## 输出规范

- **评估报告**：包含评估结果、问题清单、改进建议。
- **报告格式**：支持JSON、Markdown、HTML三种格式。
- **评估结果**：总分、等级、维度得分、问题分类。
- **改进建议**：短期、中期、长期改进计划。
- **边界情况处理**：针对不同边界情况提供处理方案。
- **最佳实践**：提供评估标准、评估流程、改进建议的最佳实践。
