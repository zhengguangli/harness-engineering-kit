# Skills质量评估维度体系

## 评估维度（6个维度）

### 1. 结构完整性（权重：20%）

**评估标准**：
- frontmatter完整性：包含name, description, when_to_use, compatibility等必需字段
- 章节结构：包含核心原则、何时使用、何时不该用、方法论、关键要点、常见陷阱等标准章节
- 格式规范性：Markdown格式正确，层级结构清晰

**评分规则（0-10分）**：
- 9-10分：完全符合harness体系规范，结构完整，格式规范
- 7-8分：基本符合规范，缺少1-2个非必需字段或章节
- 5-6分：部分符合规范，缺少必需字段或章节
- 3-4分：结构混乱，缺少多个必需部分
- 0-2分：几乎无结构，不符合规范

**检查点**：
- [ ] frontmatter包含name字段
- [ ] frontmatter包含description字段（≥20字符）
- [ ] frontmatter包含when_to_use字段
- [ ] frontmatter包含compatibility字段
- [ ] 包含"核心原则"章节
- [ ] 包含"何时使用"章节
- [ ] 包含"何时不该用"章节
- [ ] 包含"方法论"章节
- [ ] 包含"关键要点"章节
- [ ] 包含"常见陷阱"章节
- [ ] 包含"Agent 提示词"章节（如适用）

### 2. 内容质量（权重：25%）

**评估标准**：
- 清晰度：内容表达清晰，无歧义
- 完整性：覆盖skill所需的所有关键信息
- 可执行性：提供的指导可直接执行

**评分规则（0-10分）**：
- 9-10分：内容清晰、完整、可直接执行，无冗余
- 7-8分：内容基本清晰完整，个别地方可改进
- 5-6分：内容部分清晰，但存在歧义或缺失
- 3-4分：内容模糊，难以执行
- 0-2分：内容混乱，几乎无法使用

**检查点**：
- [ ] 核心原则清晰明确
- [ ] 方法论步骤详细可执行
- [ ] 示例和用例具体实用
- [ ] 无歧义表述
- [ ] 无冗余信息

### 3. 可用性（权重：20%）

**评估标准**：
- 触发条件清晰：用户知道何时使用该skill
- 执行流程明确：agent知道如何执行
- 输出格式规范：输出结果易于理解和使用

**评分规则（0-10分）**：
- 9-10分：触发条件清晰，执行流程明确，输出格式规范
- 7-8分：基本可用，个别环节可优化
- 5-6分：可用但存在困惑点
- 3-4分：难以使用，需要大量猜测
- 0-2分：几乎无法使用

**检查点**：
- [ ] "何时使用"场景具体明确
- [ ] "何时不该用"场景清晰
- [ ] 执行流程步骤清晰
- [ ] 输出格式有明确规范
- [ ] 有具体的使用示例

### 4. 设计模式（权重：15%）

**评估标准**：
- 模块化：skill结构模块化，易于理解和维护
- 可扩展性：设计允许未来扩展和修改
- 一致性：与其他skills保持设计一致性

**评分规则（0-10分）**：
- 9-10分：设计优秀，模块化清晰，可扩展，高度一致
- 7-8分：设计良好，基本符合体系设计模式
- 5-6分：设计一般，部分符合体系设计模式
- 3-4分：设计较差，与体系设计模式不一致
- 0-2分：设计混乱，无模块化

**检查点**：
- [ ] 遵循harness体系设计模式
- [ ] 结构模块化清晰
- [ ] 允许未来扩展
- [ ] 与其他skills风格一致

### 5. 文档质量（权重：10%）

**评估标准**：
- 示例丰富度：提供足够的示例和用例
- 说明清晰度：文档说明清晰易懂
- 错误处理：包含错误处理和故障排除指导

**评分规则（0-10分）**：
- 9-10分：文档优秀，示例丰富，说明清晰，包含错误处理
- 7-8分：文档良好，基本够用
- 5-6分：文档一般，缺少部分示例或说明
- 3-4分：文档较差，难以理解
- 0-2分：几乎无文档

**检查点**：
- [ ] 包含使用示例
- [ ] 包含错误处理指导
- [ ] 包含故障排除建议
- [ ] 说明清晰易懂

### 6. Agent提示词质量（权重：10%）

**评估标准**：
- 角色定义清晰：agent知道自己的角色和职责
- 执行流程明确：agent知道如何执行
- 约束合理：约束条件合理且可执行

**评分规则（0-10分）**：
- 9-10分：Agent提示词优秀，角色清晰，流程明确，约束合理
- 7-8分：Agent提示词良好，基本可用
- 5-6分：Agent提示词一般，存在困惑点
- 3-4分：Agent提示词较差，难以执行
- 0-2分：几乎无Agent提示词

**检查点**：
- [ ] 角色定义清晰
- [ ] 核心能力明确
- [ ] 执行流程详细
- [ ] 约束条件合理
- [ ] 输出规范明确

## 综合评分计算

**总分计算公式**：
```
总分 = (结构完整性得分 × 0.20) + (内容质量得分 × 0.25) + (可用性得分 × 0.20) + 
       (设计模式得分 × 0.15) + (文档质量得分 × 0.10) + (Agent提示词质量得分 × 0.10)
```

**等级划分**：
- A级（9-10分）：优秀，可作为参考范例
- B级（7-8分）：良好，符合标准
- C级（5-6分）：一般，需要改进
- D级（3-4分）：较差，需要重大改进
- F级（0-2分）：不合格，需要重写

## 评估流程

### 自动化检查（权重：40%）

1. frontmatter字段完整性检查
2. 章节结构检查
3. Markdown格式验证
4. 关键词一致性检查

### 人工评审（权重：60%）

1. 内容质量评审
2. 可用性评审
3. 设计模式评审
4. 文档质量评审
5. Agent提示词质量评审
